# 竞速模式需求记录

## 已确认的环境

- 游戏：Slay the Spire 2，public-beta v0.111.0，commit 41cef1ea。
- 游戏目录：`D:\steam\steamapps\common\Slay the Spire 2`。
- 2–4 人，BaseLib v3.4.7、RitsuLib 0.5.20；另有美化模组。
- 下载目录中的模组不等于实际启用的模组，兼容测试前需要确认启用清单。

## 比赛模型

- 玩家在同一房间准备，全部准备后房主点击“启程－竞速”。
- 每名玩家运行本地单人对局，单独选路、战斗和挑战 Boss；使用相同地图、单人战斗强度。
- 竞速连接同步玩家状态和相关抉择，包括层数、节点、血量、卡组、遗物、增益和干扰。
- 对方抉择和比赛排名可以影响本地未来游戏状态，例如下一场战斗的 buff/debuff。
- 地图显示玩家所在节点，右侧显示按进度排序的榜单。
- 允许不同角色，统一进阶等级；全员加载完成后统一倒计时。
- 排名默认按已完成累计层数，同层按先完成者在前。
- 落后达到一定层数差距后获得增益，限制叠加；数值与门槛待设计。
- 领先者在领取奖励时检查资格，可以放弃一份卡牌奖励向其他未结束玩家施加干扰；具体效果待设计。
- 进入建筑师房间即完成并向全员公告。完成者按用时排名，死亡者随后按完成层数排名。
- 所有人完成或死亡后统一结算；房主提前完成或死亡仍维持连接。

## 查看朋友信息（用户补充）

- 点击朋友头像，像原版联机一样查看朋友当前卡组、遗物和血量。
- 对方状态变化后实时更新；优先评估复用原版查看界面。
- 本功能不等同于观战画面，不能以静态面板代替下述观战需求。

## 第一幕测试终点（用户补充）

- 房主在开赛前可勾选“击败第一幕 Boss 后结束竞速”，配置同步给所有参赛者。
- 用户原文“一层 Boss”暂按第一幕 Boss 理解。
- 启用时，击败第一幕 Boss 即记为该玩家完成并公告；不是进入 Boss 房间或结束奖励选择时才判定。
- 仍等待全部玩家完成或死亡，使用与完整竞速相同的排名、等待、观战及统一结算流程。
- 未勾选时终点仍为进入建筑师房间。

## 死亡后的实时观战（用户补充）

- 死亡后可以观看其他玩家进度。
- 实现方向：接收对方操作，在本地镜像复现，允许一定延迟。
- 不采用视频直播作为默认技术方案。
- 技术待验证：完整状态与随机数快照、有序操作流、切换对象、中途加入、缓冲、偏差检测和重新同步。
- 评估原版战斗回放的可复用范围；尚未证明它能覆盖地图、商店、事件和其他完整流程。
- 观战复现必须隔离存档、比赛上报、成就及其他副作用，不能再次产生竞速干扰。

## 比赛内的个人 SL（用户补充）

- 支持玩家在比赛内单独进行 SL（存档/读档回退），只恢复该玩家的本地对局，不要求其他玩家一同回退。
- 设置中可切换是否允许 SL。暂按房主开赛前设置、全员统一遵守理解。
- 个人 SL 需要保持竞速连接，其他玩家可以继续推进。
- 已批准：房间入口恢复、保留随机状态；允许 SL 默认关闭，次数仅不限／每人 1 次；死亡直接结束，不能死亡后 SL。开赛后规则锁定。计时继续且每次 SL 额外罚 30 秒。先做游戏内恢复，不做断线或房主整场恢复。
- 回退后需要同步新的玩家状态，并让正在观看该玩家的观战端重新建立快照和操作流；不能继续套用回退前的操作序列。

### 待确认的实现建议

- 比赛计时不随个人 SL 回退，也不暂停其他人的计时。
- 比赛事件记录独立于可回退的本地存档，防止重复发送干扰或重复领取追赶增益。
- 已发送给其他玩家的干扰不撤销；收到的干扰也不能简单通过读档抹除。
- 若回退涉及已发送干扰的卡牌奖励，需要同步处理奖励消耗记录，避免既保留干扰又重新获得该奖励；具体规则待设计。

## 暂缓：局外统一读档与异常恢复

- 当前不实现由房主在局外统一恢复整场竞速的功能。
- 为应对断线、网络异常和崩溃，整场持久化及恢复值得后续考虑，但本阶段不设计或实现。
- 个人 SL 不等于崩溃重连，不视为已经支持完整的断线恢复或房主迁移。

## 增益/减益总开关（用户补充）

- 房主可选择是否启用玩家间的增益/减益机制，设置同步给所有参赛玩家。
- 暂按一个总开关控制追赶增益与领先者干扰理解。
- 基础竞速原型阶段不实现效果，也不显示可用的效果开关；后续加入机制时再提供开关。

## 当前范围

用户已授权尝试实现基础竞速原型：准备开赛、本地独立单人对局、地图位置和榜单同步、完成/死亡后的统一结算，并保留第一幕 Boss 测试终点。
SL、实时操作镜像观战、增益/减益及其开关等扩展功能留到后续。朋友卡组和遗物查看也不作为首次基础竞速原型的前置条件。
开发中必须区分本地编译/工具验证与真实双客户端联机验证，不能仅凭编译成功宣称联机可用。

### 2026-09-14 双人测试后的范围调整

本次实现音乐正确衔接、竞速前与竞速中的浮窗拖动/缩放/折叠、正确的结算文案和冻结计时，以及点击玩家名字/ID打开可关闭的玩家详情。详情包含当前手牌、完整牌组、遗物、药水、血量、格挡、能量和状态。
用户随后明确要求“先不做观战和 SL”，因此本版不接入操作镜像或读档恢复。查看牌组和手牌只提供状态详情，不宣称是观战画面。上述长期需求保留供后续使用。

随后新增：使用原版左上角玩家状态栏与玩家展开页查看卡组、遗物和血量；同步原版地图画笔。绘图按幕隔离，保留橡皮、清空以及原版多人绘图可见性设置；仍保持每人单人战斗。

0.3.0 复测后：准备设置默认右上角，进入对局后隐藏，局内设置单独打开；删除进度窗拖动和查看手牌的提示文字，收紧原版玩家栏行距。按用户提供的参考统一自定义 UI 风格。结算不能只有文字，需展示角色头像、玩家 ID 与名字、类似血条的粗时间横条及精确用时。

### 后续已授权并接入的范围（0.5.0–0.6.1）

- 游戏内个人 SL 按前述已批准规则接入，0.5.1 将按钮放入竞速进度窗，并在计时旁显示次数规则。此前“暂缓 SL”的记录是阶段历史，不再代表当前功能范围。
- 0.6.0 接入死亡／完成后的战斗操作复现、视角切换、SL 世代重建、事件文字播报和 Boss 进入广播。0.6.1 增加后台追赶与状态校验；不承诺瞬间恢复战斗中间任意状态。
- 地图只在每名玩家当前节点画圈，颜色和名字区分玩家；跟随地图滚动与缩放，保留共享画笔。
- 准备窗背景参考角色介绍做半透明；开赛 3、2、1 居中放大。
- 观战 UI 可拖动、缩放、收起，默认紧凑并上移，尽量避开怪物意图；手动布局在刷新和切换视角时保留。
- 每次发布必须在 README 累加本次新增、修改和修复，保留过往版本记录；源码 README 与发布包 README 保持一致。

### 0.6.2 补充要求

- Boss 滚动广播底部以进度条显示本条剩余播报时长。
- 提供 🤯、🤢、😅、🥰 表情按钮，所有玩家可以点击；只同步点击指令，本地播放不同大小的下落动画，各端画面允许不同。连续点击分别播放。
- 提供测试截图，区分独立 UI 渲染与 Steam 联机实测。
- 第二幕终点条件经用户确认是“击败第二幕 Boss 后完成”，沿用第一幕终点的等待和统一结算规则；不是进入房间即完成。
- 表情显示范围最终确认：广播仍全员可见，其他玩家点击发送，只给该条广播中进入 Boss 房的玩家播放表情雨；发送者和无关玩家不播放。
- 表情栏与滚动字幕放在一起，共用剩余时长，到时一同消失；连续广播的按钮分别对应各自的玩家。

### 0.6.4 观战反馈与复测范围

- 三人局：非房主先完成后无法观看另外两人；第二人完成后，两人均无法观看最后一人，持续黑屏加载后退出。后续双人局可正常观看。
- 排查必须覆盖三人中途加入、切换目标、两人同时观看一人及房主完成后继续转发，不能仅以双人正常作为验收。
- 保留原版操作镜像及状态校验，修复阶段等待和重同步相互打断，不以显示未经校验的画面替代修复。
- 本地消息模拟和战斗模型测试与真实三机联机验收分开记录；README 累计追加修复和验证范围。

### 0.6.3 补充要求

- 新增物品实际获得广播：“玩家名 获得了 物品名！”。遗物为微型帐篷、化学物X（用户所说 x药）、冰淇淋；卡牌为未掘宝石、添柴、午夜、祭品、肾上腺素、杂技、毒性爆发、大爆炸、武器库、精神过载、电流相生。分类与 ID 按 v0.111.0 原版数据核对。

- 表情发给点击时所有正在显示字幕的玩家；同一玩家的多条字幕合并为一个接收者。
- 用户明确确认：发送者自己也正在被播报时，同样播放表情雨。本条取代 0.6.2 的“发送者不显示”规则。
