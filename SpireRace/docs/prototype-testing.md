# 尖塔竞速 0.6.4 — 多人观战修复测试版

这是基础竞速原型，不是已通过实机联机验收的正式版本。
适配 Windows public-beta v0.111.0；所有参赛者必须使用相同的游戏版本和相同版本的 SpireRace。

## 0.6.4 优先复测：三人中途加入与同时观战

本次用户复现顺序：三人开赛，房主和一名玩家未完成时，另一人先完成后无法观看这两人；随后第二人完成，两名观众都无法观看最后一人，黑屏加载后退出。之后双人测试可以正常观看。本地日志显示提前排队、结束回合取消后续操作及卡牌引用缺失；另外修复了全房间重发引起其他观众一起重建的逻辑。

1. **三人全部安装 0.6.4 后重新开局**。可选第一幕 Boss 终点加快复测；不要混用上一版。
2. 让非房主 C 先完成，房主 A 与 B 分别进入不同战斗；C 在两人打过至少一回合后切入，再切换另一人。等待操作数追赶和校验后，应出现战斗画面，核对双方血量、敌方血量、手牌、能量与回合。
3. A 随后完成，A 与 C 同时观看还在战斗中的 B。B 连续出牌、结束回合、抽牌，使用生成卡牌与选牌效果；A、C 不应反复黑屏或出现“卡牌尚不存在”。也测试房主 B 留到最后的组合。
4. 一名观众返回结算再重新进入，另一名保持观看；如一人触发补数据，另一人的正常视角应继续。重发不等于对方 SL，不应让所有观众一起倒回开场。
5. 开启 SL 测试局，由 B 主动 SL，A、C 都应重建到本次 SL 的战斗；检查旧手牌和旧操作没有混入，SL 次数及 +30 秒仍正确。
6. 对方进入事件／奖励时显示文字说明；回到新战斗后重建。最后一人完成或死亡后，两名观众回到最终结算，成绩保持正确。

本地已运行真实原版战斗模型的录制／回放测试：44 条操作、30 个状态检查点、三个敌方回合，连续重建两次均一致，并人为延迟开场与下一回合验证排队保护。另运行三人消息路由／分包交错／重复补发／SL 隔离与界面遮罩检查。这里的三人测试是同进程消息模拟；**需要三台游戏客户端确认真实网络、渲染与模组组合下的效果**。

## 0.6.3 历史测试记录：获得播报与叠加字幕

1. 分别实际获得微型帐篷、化学物X、冰淇淋，以及未掘宝石、添柴、午夜、祭品、肾上腺素、杂技、毒性爆发、大爆炸、武器库、精神过载、电流相生。所有人应看到对应玩家名与物品名，物品预览和未选奖励不能播报。
2. 升级、抽出这些卡牌、生成临时战斗牌时不应播报；SL 加载已有卡牌与遗物、观战镜像也不应误报。SL 后实际再次获得指定卡牌应正常播报。
3. 两人先后进入 Boss 房、获得指定物品，检查字幕按触发消息到达顺序向下排列，各有自己的倒计时条。前一条结束时，后一条仍保留自己的剩余时间。超过四条时检查排队补位，没有丢失播报。
4. 让 A、B 同时出现字幕，由 C 发送一个表情，A、B 各播放一轮，C 和没有字幕的 D 不播放；A 自己发送时 A、B 都播放。
5. A 同时有两条字幕、B 有一条时，一次点击仍只给 A、B 各播放一轮。同一玩家最后一条字幕结束后，后续点击不再发给他；最后一条字幕结束时表情栏一起消失。
6. 快速连续点击、多人同时点击，检查目标玩家不重复播放同一点击、发送者被播报时也收到；不在接收名单中的客户端不显示。广播和表情不能拦截卡牌、地图操作。

已完成 219 项核心检查、全部 14 个原版物品模型的获得事件检查，以及 Godot 界面和网络消息模拟测试。截图为独立渲染场景，尚未执行真实 Steam 多机验收。

## 0.6.2 历史测试记录（表情规则由 0.6.3 替代）

1. 准备界面开启竞速，勾选“击败第二幕 Boss 后结束”，检查第一幕选项自动取消，朋友端同步；再切换回第一幕、取消两项、关闭竞速，核对规则。开赛后不能更改。
2. 第二幕规则下打败第一幕 Boss 应继续，进入第二幕 Boss 房间仅广播，击败后才记为完成；其他玩家仍可继续，全部结束后再结算。
3. 进入 Boss 房，检查广播底部金条从满到空，用时约 4.5 秒。多人先后进入时每条单独计时；SL／观战加速不会加快播报计时。
4. 朋友进入 Boss 房后，在该条广播下方点击 🤯、🤢、😅、🥰。只有这位朋友应看到表情雨，本机及其余玩家没有掉落动画；每次点击一轮 6 个，连续点击叠加，无冷却。进入 Boss 房的玩家自己的这条广播不显示发送按钮。
5. 广播期间多人快速或同时点击，检查只送达广播对应的玩家，没有丢失正常点击或重复播放；高密度点击时多余动画排队并最终消失。连续两人进入 Boss 房时，第二条广播的按钮应改为发给第二位玩家。
6. 广播与表情按钮约 4.5 秒后一起消失，此后不能发送，已收到的动画继续播完。在战斗、观战、SL 后和结算等待中收到广播时复测；掉落表情不应阻挡卡牌、地图或按钮操作，广播文字和时间条仍清晰。

已完成 207 项核心检查及独立 Godot 集成／渲染检查。截图使用测试数据，不是 Steam 双人实战截图；真实多机传输延迟和第二幕通关仍需复测。

## 0.6.0 战斗观战与 Boss 广播

- 自己死亡或完成后，等待／结算窗上方提供“观战 玩家名”。自己的最终成绩保持不变；仍在竞速的玩家继续游戏。
- 观战是原版战斗回放接口的本地操作复现：传输战斗初始状态、出牌与目标、选牌结果、动作恢复和回合事件，不传屏幕视频。
- 动作增量约每 100 毫秒检查一次，普通状态每 500 毫秒更新；这只是发送检查频率，不代表端到端延迟保证。切入已有战斗时从缓存重放，并以最高 4 倍动画速度追赶；恢复跟随后回到原速度。
- 顶部切换栏支持在其他玩家之间切换及返回结算；全员结束时自动回到最终结算。观战画面拦截游戏操作输入，不能替被观战者出牌。
- 被观战者 SL 时丢弃旧战斗世代并载入新快照，旧动作不能进入新战斗；切换栏显示该玩家的 SL 次数和罚时。
- 事件不在观战端进入原版事件房间，显示事件名称、当前／结束说明以及血量和金币。事件结束说明会保留在后续探索文字中。
- 有人进入 Boss 房时，全员顶部菜单下方显示“玩家进入第 N 幕 Boss 房”的金色滚动横幅、扫光与短促双击音；不阻断操作。本人 SL 重进 Boss 房也会再次通知。
- 回放数据发生顺序缺口时停止使用旧缓存并请求重新同步。观战失败仅返回该玩家的结算画面，不修改竞速成绩。

本版已完成编译、97 项核心检查、原版回放包初始／增量读写、重复与过期动作拒绝、SL 世代重建、事件播报、15 个补丁目标和界面渲染检查。**尚未完成真实 Steam 多机战斗重放验收，也未测量端到端延迟。**

建议复测：让一人先死亡；另一人在普通战斗中出牌、选择目标、选牌、结束回合，再主动 SL。核对观战端的敌人血量、手牌、回合及 SL 重建。三人以上测试来回切换与返回结算；测试事件结束播报、Boss 广播和全员结束后的最终成绩。出现卡住或不同步时保留双方日志。

## 0.5.0 游戏内 SL

- 准备界面新增“允许 SL”，默认关闭；开启后“每人 SL 次数”按钮在 1 次／不限之间切换。房主开赛前设置，全员一致，开赛后锁定。
- 局内直接点击竞速进度窗中的“SL 重试（+30秒）”。仅在玩家存活、操作与动画结束、房间快照可用时启用。若正处于出牌、选择或敌方动作，请先完成当前操作。
- 恢复到进入当前房间时的角色、卡牌、遗物、房间与随机状态。快照仅保存在内存，每次读取独立副本，不覆盖原版单人存档。
- 房主记录次数；重复网络请求不会重复扣次。读取和重打继续计时，每次额外罚 30 秒；结算用时横条和排名包含罚时，并显示 SL 次数。
- 死亡直接结束，没有复活选项或死亡时限。不支持退出游戏后读取、崩溃重连或房主整场恢复。
- 标题栏采用覆盖至首条分隔线的独立拖动热区，排除收起／关闭按钮。

- 约每 0.5 秒同步位置、血量、完成层数和终点状态；地图标记玩家位置，右侧榜单显示进度。
- 默认终点是进入建筑师房间；可勾选“击败第一幕 Boss 后结束”。
- 完成或死亡后进入等待画面。所有人结束后，显示同一份房主确认的比赛成绩。
- 途中断线或主动退出记为退赛，已经完成者保留成绩；比赛结束前房主退出会中止比赛。

尚未实现：追赶增益、干扰减益及其设置开关、断线恢复、房主迁移。0.6.0 的战斗观战属于待多机验收的测试功能。
未来增益/减益会提供房主设置的总开关；本版不显示尚不可用的效果按钮。

## 安装

1. 关闭游戏。
2. 解压 `SpireRace-0.6.4.zip`，把里面的 `SpireRace` 文件夹放到（覆盖旧版同名文件）：
   `D:\steam\steamapps\common\Slay the Spire 2\mods\SpireRace`
3. 确认该文件夹内直接包含 `SpireRace.dll` 和 `SpireRace.json`，没有多套一层同名文件夹。
4. 启动游戏，在模组设置中启用“尖塔竞速（原型）”。每位玩家都要安装。

请所有参赛者统一更新至 0.6.4，并确认没有重复启用旧包。本版沿用消息协议 8，但双方的回放时序与检查点逻辑都需要更新，不要与 0.6.3 混用测试。

本原型直接使用游戏和 Harmony 接口，没有额外新增的前置库依赖；已有 BaseLib/RitsuLib 不需要因此卸载。
首次测试建议暂时关闭快速重开、随机数预测、自动操作和改变地图/玩法的模组，减少定位问题的变量。
工具不会自动安装到游戏目录，构建包中不包含游戏程序集。

## 优先复测本次修复

1. 准备界面拖动设置窗、拉伸右下角、收起再展开，确认不会弹回原位。两人准备并启程，确认主菜单音乐停止、进入房间后正常播放对局音乐。
2. 竞速中重复操作设置窗和进度窗。折叠后应只留下展开按钮，窗口外仍能正常操作游戏；本场比赛规则开赛后锁定。
3. 两人进入不同战斗。点击对方名字，核对手牌、牌组、血量和遗物；让对方出牌、抽牌或获得状态，观察详情更新。点击“关闭”回到原界面。
4. 一人先击败第一幕 Boss，另一人继续，随后也完成或死亡。检查双方结算文字和排名一致，且计时停止增长。

真实音乐输出、网络延迟、卡牌美化模组组合以及不同显示缩放仍需本次实机复测。

## 基础竞速回归测试

1. 两人打开普通联机准备界面。房主保持“竞速模式”勾选，并勾选第一幕 Boss 测试终点。
2. 两人选择角色，点击原版启程/准备按钮；房主确认“启程－竞速”按钮可用后点击它。
3. 应出现加载等待和统一倒计时；不要通过控制台跳过加载。
4. 两人选择不同地图节点。确认一人可以战斗，另一人同时进行自己的战斗或事件。
5. 查看地图和右侧榜单，确认位置、血量、完成层数会更新。两个人的房间中都不应出现另一名玩家实体。
6. 验证一人死亡不会结束另一人的游戏，房主死亡后也要保留客户端连接。
7. 一人击败第一幕 Boss 时，应马上记为完成并公告，而不是等待领取奖励。
8. 另一人完成或死亡后，两人应看到相同排序的总成绩。若房主此时退出，另一人的成绩页应保留。
9. 后续再测试 3–4 人、不同角色、完整建筑师终点及客户端断线。

要复现房主死亡、客户端死亡、房主领先、客户端领先等不同组合，通常需要多次短局。

## 原型限制

- 固定地图模式绕过原版的地图生成修改钩子，因此暂不承诺兼容会改变地图的卡牌、遗物或其他 mod。
- SL 使用内存快照，仅能在当前游戏进程内使用。关闭游戏会丢失本场竞速，不支持局外续局。
- 排名以完成层数为主；事件完成、战斗胜利、离开非战斗节点时更新。未知房间等边界行为需实机检查。
- 本版是好友间可信客户端模型，没有反作弊系统。网络时钟校准不能保证严格赛事级的时间精度。
- 界面位置和字体仍需在实际分辨率、UI 缩放及美化模组组合下确认。
- 没有 Steam 双客户端实测前，不能视为联机流程已经验收。
